# 随身音乐架构

`portable-music-downloader` 面向能独立播放音乐的智能手环、智能手表和蓝牙耳机。
当前设备适配是 U 盘音乐目录读写；0.2.0 音源为歌曲宝和歌曲海，仅接入页面普通 MP3 播放源。
音源接口位于 `src/shared/providers`，新增来源需独立实现页面解析、播放请求和响应解析；设备传输流程不依赖来源。

参考本机 `school-ebook-downloader` 当前工作目录：TypeScript / Vite / pnpm，
`src/background`、`src/content`、`src/shared`、`src/popup` 分层，`public/manifest.json`、
`scripts` 构建校验与打包，`.github/workflows` 持续集成。参考仓库中的未提交修改保持不变。

音乐管理页沿用 `popup.html` 入口命名，通过扩展图标打开独立标签页，保证目录选择、
试听和长下载队列不会因弹窗失焦而关闭。

- background：请求队列、音源小窗会话、严格的消息入口和空闲会话回收。普通请求复用最小化小窗内的接口桥接，CF 验证时展开小窗供用户处理；既有扩展自建标签页会迁移到小窗。
- content：只在必要时注入自包含桥接脚本，在扩展自有歌曲宝或歌曲海会话中读取或请求对应白名单接口；不执行站点脚本。
- shared：安全的页面解析、消息类型、音频验证、ID3 元数据、本地目录与 IndexedDB。
- popup：左侧搜索与下载，右侧设备目录列表及曲库；保存设备名称、切换与移除记录，并区分电脑本地目录和设备下载目标。隐藏的音频元素由歌曲按钮控制，不显示底部播放器。

音源 HTML 仅作为数据解析，站点脚本不会在扩展页面执行。获得普通 MP3 播放源后，
扩展页面下载、验证格式/解码时长和传输完整性，再写入用户明确选择的目录；来源提供原始时长时额外检查短试听。不接网盘和 FLAC 通道。
动态地址仅在内存中短暂复用；恢复队列会重新解析。人工验证及额度限制不会自动绕过。

会话页不会因搜索词或歌曲变化而逐次导航；只有收到验证页时才导航到对应页面。
每个来源拥有独立串行请求队列和 `storage.session` 状态；空闲回收在对应来源的队列中执行，避免关闭正在使用的会话。待人工验证的小窗不会自动回收。
会话被清理或关闭后会重新尝试直连，保留的状态仅包含窗口/标签页编号、时间与验证状态。

歌曲、缓存、播放状态和队列去重以 `source:id` 标识。来源切换递增搜索序号，忽略旧响应和旧试听请求；队列继续使用入队时的来源，限额或验证仅暂停同来源任务。
队列保存来源、目录 key 和目标类型，不依赖当前选中的设备或来源；本地下载不改变设备选择。0.1.0 队列与已有歌曲记录缺少来源时默认歌曲宝。
旧队列未保存目标类型时视为设备目录任务。重新打开页面后，所有未完成项恢复为暂停状态。
popup/devices 独立查询 `chrome.system.storage` 并监听插拔，只保留可移动存储设备。异步刷新使用版本号避免覆盖较新的插拔状态，页面关闭时移除监听。
主页面显示已保存的音乐目录与添加卡片；添加弹窗列出当前发现的可移动存储设备，提供刷新和手动选择目录。已添加设备复用目录句柄及曲库 key。临时设备编号不持久化；已授权设备仅在名称和容量组合唯一时关联，旧目录仅在名称唯一匹配且可读时关联，存在歧义时手动选择目录。
第一版在存在已绑定目录时隐藏添加卡片，移除最后一个记录后恢复；保留添加流程和多设备实现，不清理历史设备记录。
初次连接才打开目录选择器；刷新设备不请求目录权限。重新打开或接入时只检查已有授权并扫描可读目录，不自动发起授权或恢复下载。设备断开时停止该目录的本地播放并暂停其队列，目录访问状态仍由真实读取检查决定。
目录选择、访问检查、扫描及本地播放只申请读取权限；发送和删除时才从用户点击中申请写入权限。
扫描跳过系统元数据目录及 macOS 的 `._` AppleDouble 文件；启动时清理旧曲库中的 AppleDouble 缓存记录，不删除设备文件。
扫描完成后，在同一个 IndexedDB 事务中保存新增、变化和移除的缓存记录；扫描中断不会提交部分扫描结果。未变化的 MP3 复用已有元数据。
下载进度按动画帧合并，只更新当前任务的文字与进度条，不逐个数据块重建整张队列。封面对象 URL 在文件变化、移除或切换曲库时回收。
播放请求按序号检查；迟到的文件读取和播放错误不会覆盖较新的播放。已关闭验证码的旧响应也不会写入新的验证码弹窗。详情总是重新获取，已移除从未命中的详情缓存；短时播放地址缓存仍用于下载复用。
目录可读取不代表实际写入必然成功；文件系统拒绝写入时显示暂不可写并暂停该目录的待处理任务。
移除设备记录会移除其未完成设备任务，不删除磁盘文件；同一目录同时用作本地和设备目标时共用曲库 key。

Release 使用单个 Ubuntu 任务构建，保存 artifact，版本标签同时生成 GitHub Release。Chrome / Edge 两个发布任务依赖 build，分别受 `chrome-web-store`、`edge-addons` 环境的 Required reviewers 保护。
`release:build` 只运行类型检查、构建、静态安全检查与 ZIP 打包；单元测试、夹具、Vitest 配置及相关依赖已移除。
推送标签或手动运行 Release 后先构建，再在同一次运行中等待人工审批。点击 Review deployments 批准相应环境后，发布任务下载本次构建的同一个 ZIP，核对 SHA-256 与 Manifest 版本，再提交对应商店。普通分支不触发商店发布；main 与版本标签可以发布。
私有仓库使用 Repository secrets，保持 ebook 的 `CWS_*` / `EDGE_*` 变量名，通过手动触发代替 Environment Required reviewers。
启用原生审批前须公开仓库，并在两个环境中设置 Required reviewers；单独在 YAML 中引用 environment 不等于已开启审核。凭据缺失时发布脚本在请求商店之前终止。详见 [发布说明](publishing.md)。
