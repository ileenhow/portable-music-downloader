# 下一版：多音源搜索与下载

更新日期：2026-10-14。0.2.0 本地实现已完成，尚未提交商店。本文保留网页研究记录，并记录实际接入与后续候选。

目标是在现有界面中选择不同音乐来源，下载完整 MP3 到电脑或已绑定设备。页面仍保留左侧搜索、右侧设备曲库和每首歌曲的三个圆形按钮。

## 0.2.0 已实现范围

按用户最新要求，仅处理页面播放器使用的普通音质 MP3，不接高品质网盘或 FLAC。

- 音源接口已拆到 `src/shared/providers`，首批为歌曲宝和歌曲海；搜索区提供原生来源选择框，并保存上次选择。
- 歌曲、任务、缓存和播放状态使用来源标识；旧数据默认歌曲宝。切换来源会忽略旧搜索响应，不替换已经入队的版本。
- 各来源拥有独立的请求队列、验证小窗和限额暂停状态，设备写入仍逐首执行。
- 歌曲海真实搜索 HTML、详情 HTML 和接口响应已通过实际构建产物的解析联调：15 条结果，“晴天 — 周杰伦”，普通音质类型 0。
- 通过匿名 HTTP 请求复核页面播放器接口，实际获取 MP3：4,317,292 字节、269.792625 秒、44.1 kHz 双声道、128 kbps。样本只保存在临时目录，未写入设备。
- 本地预览已检查来源切换和重新打开后记忆；类型检查、生产构建和既有安全检查通过。未新增或运行单元测试。
- 实际 Chrome / Edge 扩展中的完整交互、验证小窗与设备写入仍需人工复核；本次未自动加载或发布 0.2.0。已提交的 0.1.0 ZIP 保留。

## 歌曲海更换节点后的实际流程

### 连接、搜索与详情

此前 .com 两次出现 `ERR_HTTP2_PROTOCOL_ERROR`，发生在网站验证页面出现之前。用户更换 Clash 节点后，同一内置浏览器可直接打开首页、搜索和详情。这个前后变化支持“先前失败与节点或代理线路有关”的判断，但不足以定位具体 DNS、代理或 HTTP/2 环节。

- 本次会话未出现 CF 页面、人工验证码或登录要求。不能据此断言新会话、其他节点或高频访问永远不需要验证。
- 在首页实际搜索“晴天 周杰伦”，进入 `/search?s={关键词}`，返回 15 条结果，包含原版、现场版、串烧和翻唱。
- 点击第一条“晴天 — 周杰伦”新开 `/play/326`。本次搜索结果未观察到分页，其他关键词的分页待验证。
- 证据：[搜索截图](source-research/gequhai-search.jpg)、[详情样本](https://www.gequhai.com/play/326)。

### 试听、音频来源与下载

- 使用页面 APlayer 播放控件，进度实际从 `00:00` 推进到 `00:22`，页面标示总时长 `04:29`。尚未校验整首音频文件，不能把页面时长当作下载完整性的证明。
- 浏览器已观察到 `/api/music` 请求以及 `car-er.kuwo.cn` 上的 `.mp3` 音频资源；该音频文件名为 `M500000bYDlc2XxKLs.mp3`。
- “下载歌曲”打开音质弹窗，上部提供扫码入口，下部“直接下载”可展开三个选项：高品质 MP3、无损 FLAC、试听音质。
- 高品质 MP3 和无损 FLAC 分别指向夸克分享。已观察到夸克分享标签页，没有登录网盘或完成文件下载。
- 上轮内置浏览器的“试听音质”入口没有静态 `href`，点击后虽观察到 `/api/download-log`，但没有确认文件下载。本轮开发通过静态阅读公开播放器代码及匿名实际请求，补验了普通播放源，不依赖该网盘弹窗。
- 普通接口为 `POST /api/music`，表单 `{id: 页面 play_id, type: 0}`；页面使用 `X-Requested-With: Http` 和固定的 `X-Custom-Header: Key`。实际响应为 `code:200`，音频地址在 `data.url`。这些固定头不是用户 API 密钥。
- 已观察到旧播放参数返回业务 `code:403` 和“会话已过期”。适配层会重新读取同一来源、同一歌曲的详情并重试一次；其他访问异常可使用自有页面会话回退。过期播放参数不触发验证码小窗，真正的验证页仍通过原有小窗流程处理。
- 新实现使用本地解析器读取 HTML 的静态参数，正常发出播放请求；没有在扩展中执行下载的站点脚本，也没有绕过验证或下载限制。临时地址有效期、分页和额度还需进一步人工检查。

证据：[展开的下载弹窗截图](source-research/gequhai-download-options.jpg)。

### 与歌曲宝的接入差异

用户可见流程都包含搜索、详情、试听和下载入口，但协议不同：歌曲海是 `/search?s=…`、`/play/{id}` 和已观察到的 `/api/music`；当前歌曲宝适配器使用 `/s/…`、`/music/{id}`、`appData/play_id` 和 `/member/common-play-url`。需要单独适配，不能只替换域名。

歌曲海这个样本与放屁网样本使用相同的音频文件名，分别由酷我的不同主机返回。这说明该曲目可能共享音频上游；不证明三个网站的运营主体、曲库或解析额度相同。

## 放屁网实际流程

### 搜索与验证

1. 打开站点出现 Cloudflare 安全验证，首次访问自动通过，没有操作人工验证码。
2. 在页面搜索框输入“晴天 周杰伦”，进入 `/s/晴天%20周杰伦`（实际 URL 使用 UTF-8 编码）。
3. 主搜索列表显示 6 个版本，歌曲详情路径为 `/music/{数字编号}`。
4. “播放&下载”链接使用 `target="_blank"`，点击后新开歌曲详情标签页。

主列表编号：`11561938`、`11566247`、`11566251`、`11584094`、`11566252`、`11574391`。本次列表没有下一页链接，其他关键词的分页行为尚未验证。

证据：[搜索截图](source-research/fangpi-search.jpg)。

### 试听与下载

样本：[晴天 — 周杰伦，11561938](https://www.fangpiw.com/music/11561938)。

- 点击播放后，页面音频地址来自 `kw-er.kuwo.cn`。音频元素显示时长 `269.746667` 秒、加载状态 `readyState=4`，播放进度实际推进；随后已暂停。
- “下载歌曲”点击后弹出“请选择音质”，并非只有按钮静态链接指向的网盘入口。
- 推荐选项是“下载高品质 MP3”，链接通过 `/dp/{编码链接}` 指向夸克分享。未登录网盘或完成该通道下载。
- 备用选项是“下载低品质 MP3”，页面提供 `kw-er.kuwo.cn` 的 `.mp3` 链接，查询参数含 `bitrate$128`。这是页面标注，不代表已检测到文件的实际码率。
- 在内置浏览器尝试下载备用链接，下载等待超时，随后出现 `ERR_HTTP_RESPONSE_CODE_FAILURE`。未取得可校验的音频文件，具体失败原因未知；不能宣布完整下载流程已通过。
- 第二个已在页面推荐区观察到的版本 `/music/402856` 显示“验证成功，正在等待站点响应”，尚未进入详情页，下载方式待验证。

临时媒体链接含易变化的路径参数，因此本文不保存整条链接。音频格式、完整文件大小、下载请求条件和地址有效期需在后续成功下载时确认。

[详情及下载弹窗局部截图](source-research/fangpi-detail-cloud.jpg)仅记录首次弹窗上部，完整的两个选项以本次页面 DOM 观察为依据。

### 是否是歌曲宝的“马甲”

可以确认相似的搜索/详情路径、页面操作和 CF 验证；放屁网这个样本使用酷我音频，当前扩展也处理歌曲宝返回的酷我音频地址。上述现象支持“可能使用相似模板或上游”的推断。

尚无运营主体、相同查询的完整结果、同一歌曲详情数据或接口响应的对照证据。本次歌曲宝对照页停留在验证后的等待响应状态。因此不能确定它们是同一运营者，也不能确定所有歌曲和解析额度共用。

产品上暂按“备用入口候选”处理。后续用相同关键词和相同版本，比较曲库差异、解析失败与额度是否独立，再决定是否值得显示为独立来源。

## 0.2.0 的界面与行为（已实现）

- 在左侧搜索区放一个紧凑的来源选择框，默认歌曲宝，记住用户上次选择；选择框不改变两栏比例。
- 一次只搜索选中的来源。切换来源后以当前关键词重新搜索，不混入上一来源的结果。
- 歌名与歌手仍在左侧上下排列；右侧仍为下载、发送到设备、播放三个图标。暂不支持的操作禁用，并通过悬停提示说明原因。
- 设备绑定、名称编辑、容量显示、曲库筛选和单设备限制保持现有交互。
- 验证只打开对应来源的一个小窗。明确显示正在验证哪个站点，完成后复用该来源会话。
- 一个来源失败时显示可理解的原因，用户可切换来源重试；不自动替换为其他歌手、翻唱或版本。

## 已完成的接口拆分

0.1.0 在 `src/shared/source.ts` 和后台固定歌曲宝的页面、播放及验证码协议。0.2.0 保留其原解析模块，在 `src/shared/providers` 提供来源注册和分别解析；后台请求与界面通过统一的消息协议调用。搜索 HTML 由所选来源的本地解析器转换为标准歌曲结果。

| 修改范围 | 实现 |
| --- | --- |
| 歌曲身份 | 增加 `source`，统一使用 `source:id` 作为缓存、播放状态、队列和去重键；歌曲编号格式由各音源校验 |
| 音源适配 | 为每个来源封装搜索、详情、试听解析、下载解析、验证方式和能力；解析逻辑使用随包发布的本地代码 |
| 标准结果 | 搜索输出统一歌曲信息与分页游标；HTML 解析封装在适配层，通过现有页面桥接或本地解析模块实现，界面不再调用固定歌曲宝解析器 |
| 下载能力 | 区分完整音频、短试听、直接下载、网盘入口、受限与暂不可用；能试听不等于能下载 |
| 消息协议 | `SEARCH/DETAIL/RESOLVE/CAPTCHA/VERIFY` 携带来源；重试和验证码回调必须指向原来源 |
| 会话管理 | 每个来源独立存储自己的窗口、标签页、验证状态和请求队列；设备目录写入继续串行 |
| 历史迁移 | 旧队列和旧 `sourceId` 默认属于歌曲宝；不修改已有 MP3 内容或文件名 |
| 权限和发布资料 | 实际接入时只添加必要的站点访问权限，更新新增数据接收方、隐私政策和商店说明；不提前把候选写成已支持 |

播放、详情缓存和队列都需要加来源，避免不同站点恰好同号时播放错歌、错误去重或任务恢复到错误站点。临时媒体 URL 仍只保存在内存，恢复任务时重新解析。
